# Transfer ledger - 3840x2160 source, 1920x1080 working, decode `cuda`, transfer order `reduced`

Generated by `tests/unit/collect_transfer_ledger.py` on code under test `740c78a0f96b3927bd3fc1c27efa3fc93d5c51ee`.

A payload size is arithmetic on a buffer. A transfer byte count is a measurement. A row whose measurement is `unavailable` has no number on purpose, and `0` in a transfer column always means measured-and-really-zero.

This ledger describes the `reduced` order: one filter pass writes both the BGR plane and the RGBA plane, the BGR plane goes to the NVOF bridge as it stands and is reordered on the GPU, and the residual composite reads the host's RGBA output where the host wrote it.

## Measurement rules

- `measured`: a counter, or the return value of the read or write that did the moving, from the run itself
- `estimated`: arithmetic on a format, standing in for a copy nothing counted
- `logical`: the size of a buffer a stage was handed, or wrote; not a bus transfer
- `unavailable`: nothing observes this, and no number - including 0 - is claimed
- `not_reached`: the branch did not run in this configuration

Statuses a row may carry: `ELIMINATED_PROVEN`, `REDUCED_PROVEN`, `BLOCKED_PROVEN`, `not_yet_evaluated`.
