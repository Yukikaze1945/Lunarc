# SDR 10-bit NR 色彩修正

## 修改原因

旧路径把 SDR 10-bit 转成线性 BT.709 后，继续使用 HDR 的压缩代理和按通道亮度倍率重构。这会改变模型收到的暗部码值；用量化后的局部斜率还原模型输出，也会放大通道间的细小偏差。

画质控制原先使用 RGB 灰度分量分离明度和色度，与 Magpie 的 Oklab 控制语义不同。“色度强度 0”并不能保持原片的感知色度。

## 当前实现

- SDR 10-bit 的 FP16 主画面继续保存有符号线性 BT.709；模型输入改为对应的 BT.709 RGB 码值，仍使用 FP16。
- 模型输出通过 BT.709 逆传递函数转回线性光，残差为 `EOTF(NR) - EOTF(input)`。不使用 HDR 压缩肩部、逐通道斜率除法或亮度倍率修正。
- 单层开启源细节保留时，输出为 `source + strength × U(residual)`。
- 单层关闭源细节保留时，输出为 `lerp(source, U(EOTF(NR)), strength)`。模型依然运行；100% 工作分辨率不需要放大。
- 多层融合继续使用线性光残差求解原有数据一致性目标。HDR 仍使用原有 HDR 重构方案。
- 明度、色度和色相保护改在 Oklab 中处理。SDR 10-bit 的画质控制明确区分线性主画面与显示码值；HDR 直接处理有符号线性 scRGB。
- SDR 超出色域的感知色彩沿固定色相方向降低色度，不逐通道硬截断。此映射不用于 HDR。
- GPU post-control ABI 升到 2，必须与更新后的 Python 接口一同使用。SDR NR 新增独立原生接口标识，旧桥接库不会静默继续使用旧重构。

Oklab 使用 [Björn Ottosson 公布的矩阵](https://bottosson.github.io/posts/oklab/)，控制实现由本项目编写。

## 当前状态
