# 图片单帧渲染与两份结果缓存

日期：2026-10-16。范围：图片工作台及图片保存；视频调度、NR 数学目标和编码链不变。

## 需求与决定

导入先显示原图，默认由“渲染一帧”触发处理。实时开关只在明确开启后随设置变化重算。一个 GPU 所有者线程串行处理，忙时合并后续请求为最新状态；手动模式不因改参数自动运行。

默认省显存模式按链路卡片执行：

```text
原图 → 卡片 A → 完整像素回读到 RAM → 关闭 A 的资源
     → 卡片 B → 完整像素回读到 RAM → 关闭 B 的资源 → 最终结果
```

中间数据保持既有处理域：SDR RGBA8 / HDR 线性 scRGB FP16。完成同步回读后，严格关闭特效、交换资源、会话与所属 CUDA 上下文，才允许下一卡片创建。复用既有各阶段实现，不增设滤镜、降低精度或自动切块。单张 NR 卡片内部的多层融合/顺序算法保持现状，其中的内部会话可能同时存在；不承诺单个模型不会超出显存。

保留快速模式，用原完整链执行，保存最终原始像素而不是显示映射图；模型可继续常驻。较低显存方案付出 CPU/GPU 传输和模型重载成本，快速模式付出常驻资源成本。用户可选择，不根据未知预算静默改变画质。

## 缓存与显示

- 不可写的完整尺寸主结果保存在 RAM，最多本次与上一次两份；第三次成功提交删除最旧项。失败不替换成功结果，关闭后端清空。
- 每份记录源路径、源大小/修改时间、像素参数及选中运行库的签名、实际 SDR/HDR、尺寸、诊断。执行策略不属于像素签名。
- 浏览器用 CPU 生成成对显示图；HDR 映射仅供 SDR 显示。桌面 HDR 用不带模型的显示资源上传缓存并呈现 FP16/scRGB。对比线和视图变更不推理。
- 两图尺寸不同时仅在显示时缩放参考图；各缓存的色彩解释、导出像素不变。
- 推理资源释放后缓存仍保留；原生显示仍需要一对显示资源，不宣称总显存归零。

## 保存与失败处理

默认保存已渲染缓存，只转换文件格式。该 CPU 路径位于 GPU 健康检查和所有权锁之前，即使 GPU 忙也不重新推理。重新渲染保存仍可选择。

源文件改变时拒绝保存旧结果。参数变化时要求重新渲染或用户明确选择旧结果，不把旧图当成新参数结果。缓存被淘汰返回清晰错误。缓存 API 使用既有本地认证，输出沿用原路径与覆盖检查。

清理失败阻止进入下一阶段，不以降精度、切块或复用可能失效的指针继续运行。原生设备错误沿用后端熔断机制；已暂停或正在释放时拒绝迟到的原生显示请求。
