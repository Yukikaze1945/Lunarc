# 预览参数更新

Windows 工作台视频统一使用 [原生 GPU 预览](native-hdr-preview.md)，SDR 8-bit、SDR 10-bit 和 HDR 的中央滑块都直接重绘 GPU 缓冲。下文关于 JPEG 回读的描述适用于浏览器、静态图片、光流诊断和文件对比页。

预设、参数折叠、底栏指标和时间轴选区的使用方式见 [预设与选区预渲染](workbench-presets.md)。

## 本轮改动

- 每个参数写入批次完成后立即通知预览，不再等整个写入队列清空。
- 参数刷新保留当前视频、画面位置和显示确认状态。当前 GPU 工作完成后可以先显示结果，再处理最新参数，避免拖动时不断丢帧而不出画面。
- 切换视频、重新加载素材和拖动进度条会使旧请求失效。原生预览切换视图时重绘已有 GPU 画面。
- 暂停时保存一份独立的 GPU 源画面和后处理前结果。修改明度、色度、色相保护等画质控制时，复用这一帧，不重复运行 NR 或推进时域历史。
- 缓存保留原处理分辨率和精度。SDR 10-bit/HDR 使用 FP16；缓存只在 GPU 内复制，播放时不逐帧增加缓存复制。切换素材或尺寸时释放缓存。
- 缓存显存不足时保持完整处理路径和原画质，在诊断中记录缓存不可用原因。其他 CUDA 错误仍明确报错。
- NR 运行参数支持组合渲染链中的会话复用。单层残差倍率修改不再重建解码器和模型会话；尺寸、模型运行库及不支持热更新的结构参数仍重建。
- 10-bit/HDR 预览直接从线性结果生成显示画面，不执行导出用的 P010 转换。导出编码流程保持原样。

后处理缓存位于现有画质控制之前。如果渲染链在它之后还有 VSR 或 DLAA，这些后续阶段仍会按原顺序处理修改后的画面。

## 诊断

预览新增 `post_only_reprocess`、`inference_reused` 和 `post_cache`。缓存的 `private_plane_bytes` 是两份独立 CUDA 平面的容量，不代表预览的全部显存。`host_image_bytes=0` 只描述缓存复制；显示画面仍会回读并经 JPEG、WebSocket 传输。

参数请求返回 `preview_revision`；预览帧报告它实际使用的设置版本及是否已是最新版本。前端记录参数写入耗时和最新参数到显示机会的延迟。浏览器的显示确认不等于显示器实际扫描输出。

前端编译及 16 项调度、缓存和会话生命周期检查通过。未运行新的 GPU 性能基准，未宣称具体帧率或提速倍数。该改动已纳入 1.0.0 Beta 安装版。

## 多层预览与顺序堆叠（2026-10-12）

- 双层、三层现在默认“顺序堆叠”：第二层处理第一层的完整输出，第三层处理第二层的完整输出。各层拥有独立 NR 会话，可使用相同分辨率。原有独立多尺度数据一致性融合仍可在高级选项中选择；“仅第一层”用于对照。这三种模式不会用同一个标签混淆。
- 主参数区增加第一、第二、第三层页签，各层独立设置风格、NR 强度、局部色调、局部结构、皮肤结构及自动遮罩。第一层仍使用原有字段，`layer_settings` 保存额外层覆盖；预览与导出共用解析规则。切换多层时复制第一层作为初值，之后各层单独保存。
- “调整本层参数”直接在对应卡片中展开控件。修改某层 NR 参数，只更新该层的 Feature 18 选项；顺序堆叠还会重算所有后续层，保留前面未改变的层。独立融合则复用未改变层的推理结果，重新融合。
- 暂停在同一源帧时，安全的 NR 参数热更新可复用前置 DLAA/VSR 输出及原画面的显示结果。播放、换帧、切换素材、尺寸或前置阶段设置时失效，不跨帧复用。缓存描述符由现有 GPU 资源所有者持有，不新增 CPU 图像往返。
- 图层权重、β、迭代上限、误差阈值及多层残差强度支持热更新。新增原生 `gpu_fusion_update_parameters`，保留原滤波计划和 GPU 工作纹理，更新原始/观测空间求解的权重与阈值。旧 DLL 只重建求解器，保留解码器和 NR 会话。
- 诊断增加 `layer_parameters` 和 `layer_inference_reused`，各层调用数只统计实际 Evaluate，不把缓存当作新推理。

## TrueHDR

增加最终 SDR→HDR10 转换卡片，提供对比度、饱和度、中灰亮度、目标峰值亮度和 AI 去色带。调用 NVIDIA TrueHDR 特效，不用普通调色模拟 HDR。调整这些控件时复用后处理前的 GPU 画面，不重新运行 NR 或建立解码会话。模块安装及精度边界见 [TrueHDR 说明](truehdr.md)。

## 本轮检查范围

- 23 项预览调度、参数、缓存、TrueHDR 合约和生命周期检查，3 项前端多层设置检查通过；前端构建及原生 C++ 编译链接通过。
- 320×192 的真实 GPU 短帧检查确认单/双/三层输出有差异，双/三层使用独立会话，后续层输入为上一层输出。修改第二层后调用数为 `[1,2,2]`，复用第一层及前置 DLAA。
- SDR8 三层、SDR10 三层及 TrueHDR 预览通过。TrueHDR 控件热更新后画面改变，会话代数保持不变。
- 两帧 TrueHDR 导出经 ffprobe 确认 HEVC Main10、yuv420p10le、PQ、BT.2020 和 limited range。

这些是功能检查，不是 4K 性能基准。未测量本轮优化前后的 4K 显示帧率，性能仍为 `NOT_CHARACTERIZED`。显示画面仍经回读、JPEG 和 WebSocket；不能声称整条预览链路没有主机流量。

证据保存在本机忽略目录 `build/sequential-check`，不加入源码发布。运行中的后端需完全退出，再运行 `run_gui.bat` 加载新代码；启动脚本也会应用因 DLL 占用而暂存的构建。安装版未更新。
