# 多尺度融合求解器

本页描述 2026-10-12 的实现和本机短测试。只影响实验性的双层、三层数据一致性融合；单层 NR 不走这个求解器。

## 目标与数值标准

目标保持不变：

$$\min_r\sum_i w_i\|D_i r-r_i\|^2+\beta\|r-r_0\|^2.$$

`D_i` 使用现有 Lanczos 计划；`D_iᵀ` 累加所有边界重复索引。`r0` 仍是当前帧第一层残差的 Catmull-Rom 放大结果。HDR 残差在有符号线性 scRGB 中计算，FP16 主色转换为 FP32 工作向量后求解。负值和高于 1 的亮度不进入 SDR 钳位。

令 `H = βI + Σ w_i D_iᵀ D_i`、`b = βr0 + Σ w_i D_iᵀ r_i`。所有新路径以 `||b-Hr|| / ||b-Hr0||` 检查最终收敛；CG 递推残差只用于判断何时值得复查。复查未达标时，GPU CG 从真实残差重启方向，仍受原迭代预算限制。非有限值、非正步长分母和预算不足返回错误。

## 默认路径

- CG 步长、方向系数、残差范数和状态保存在 GPU 的 32 字节控制包中。
- 小于 3840×2160 总像素的网格，每批最多调度 4 轮，再读取状态。已收敛的轮次跳过向量和滤波处理；点积仍执行必须经过的组同步。
- 4K 及更大网格按单轮检查。测试中，批量多调度的大网格归约抵消了减少同步的收益。
- 全图 FP32 工作纹理由 12 张减到 7 张，向量和累加器复用已有资源。各层临时纹理、NR 会话和传输资源另外计数。
- ForwardX / ForwardY 按实际 tap 数编译展开的 shader。只移除尾部全零补位，不截断有效采样，也不改变滤波器。
- 收敛后的复查不再把递推范数直接当成原方程误差。

颜色接口和 ABI 版本保持兼容。诊断扩展为可选接口；使用旧 DLL 时不会要求它提供新统计。

## 等价的观测空间路径

令 `A` 依次堆叠 `√w_i D_i`，`e` 依次堆叠 `√w_i (r_i-D_i r0)`。可以求：

$$ (\beta I+AA^\top)z=e,\qquad r=r_0+A^\top z.$$

实现只应用算子，不生成稠密矩阵。每轮先对全部层计算同一个 `Aᵀ` 累加，再分发回各层，保留交叉耦合。收敛标准检查 `Aᵀ(e-(βI+AAᵀ)z)`，对应同一个原方程残差。

Jacobi 原型使用 `β + w_i diag(D_i D_iᵀ)`。相同滤波行中落到同一边界像素的权重先合并，再平方。预条件范数不能代替最终原方程复查。预条件 CG 的背景见 [Netlib Templates](https://netlib.org/templates/templates.html)。

观测空间和 Jacobi 已有 GPU 实现，但本机测试没有证明速度收益，默认关闭。研究时可在启动进程前设置：

| 环境变量 | 值 |
| --- | --- |
| `LUNARC_FUSION_SOLVER` | 留空：默认全图 GPU CG；`primal`：全图 GPU CG；`observation`：观测空间；`legacy`：CPU 控制的全图 CG |
| `LUNARC_FUSION_PRECONDITIONER` | 留空：无预条件；`jacobi`：仅用于观测空间 |

这些选项用于算法实验，未增加工作台参数。

## 本机短测试

显卡为 RTX 5060 Ti。预览测试使用同一 1280×720 SDR 短素材，每条路径依次处理帧 0、1、2。下面取帧 1、2 的平均值，避开首次初始化。时间是已完成原生调用的 CPU 墙钟时间，包含驱动提交及等待，**不是 GPU 时间戳或完整导出 FPS**。

| 模式 | 旧融合耗时 | 新融合耗时 | 每帧 CG 标量同步 | FP32 工作纹理逻辑容量 |
| --- | ---: | ---: | ---: | ---: |
| dual 50% / 75% | 8.45 ms | 7.25 ms | 13 → 3 | 197.89 → 127.58 MiB |
| triple 40% / 67% / 85% | 15.67 ms | 10.46 ms | 17 → 3 | 214.24 → 143.93 MiB |

迭代数分别保持 6、8 轮。最终真实相对残差均小于 0.001。预览每层会话 ID 独立，单层结果没有融合求解报告。

同一组短预览中，双层 NR 推理总耗时为旧 7.74 / 新 6.88 ms，三层为旧 13.01 / 新 10.52 ms；NR 模型及调用未改动，不能把这部分波动归因于融合优化。双层 CPU fence 等待约 6.24 → 5.86 ms，三层约 12.58 → 8.88 ms。样本少且没有锁定 GPU 时钟，以上结果只能描述这次运行。

4K 有符号 HDR 合成测试使用 50% / 40% / 25% 三层，共 47.25% 的全图像素。每条路径复用会话处理同一组观测四次，取后三次的中位数；没有 NR 推理、解码或编码。夹具上传和最终输出回读在计时范围外。

| 4K 路径 | 完成耗时 | FP32 逻辑容量 | 结论 |
| --- | ---: | ---: | --- |
| 旧版 CPU 控制，递推残差停止 | 115.82 ms | 1.742 GiB | 对照，不包含新增原方程复查 |
| 当前 CPU 控制，含原方程复查 | 121.92 ms | 1.742 GiB | 对齐新误差标准的对照 |
| 当前默认全图 GPU CG | 123.00 ms | 1.124 GiB | 时间接近；工作纹理少约 633 MiB |
| 观测空间 GPU CG | 140.93 ms | 0.929 GiB | 更省向量空间，但更慢，不自动启用 |
| 观测空间 Jacobi 原型 | 168.44 ms | 0.929 GiB | 未显示收益，不默认启用 |

观测空间两行来自独立的短原型运行，调度批次不同于最终默认路径，不能用来做精确的速度排名。默认路径相对旧版有额外复查成本；**这轮没有实现 4K 加速**。

默认 4K 路径的 FP32 committed texture allocation 为 1,235,484,672 字节；旧版为 1,903,951,872 字节。NVML 每 10 ms 采样的整卡已分配显存峰值约为旧版 7.40 / 新版 6.72 GiB，包括其他程序、CUDA 和传输资源；它不是进程专属峰值，也不保证捕获瞬时最高值。逻辑容量、committed allocation 与整卡采样不可混用。

## 验证范围

- 全量单元测试：1770 通过、3 跳过。随后涉及 HDR 诊断及测试计时语义的定向复查：300 通过。
- 独立稠密矩阵参考：全图、观测空间、Jacobi 和热启动得到同一目标的解。
- GPU D / Dᵀ：64×48 和 65×49，包含非均匀权重、边界重复、负值和高亮。最大配对相对误差约 `1.12e-7`，D3D12 错误数为 0。
- GPU HDR 合成及 Jacobi 实验：FP16 输出、目标和一致性下降、参考误差、错误及预算语义通过。SDR 合成夹具与归档结果逐字节一致。
- HDR dual / triple 三帧真实 GPU 导出：各 27 项检查通过，包括独立会话、每帧收敛、重置、时间戳、Main10 / PQ / BT.2020、流映射、音轨字幕数据、附件、章节与 metadata、源/中间/最终 SEI 137 和 144。
- 导出测得的各层和融合图像 host 边界为 0；标量回读单独记录。预览仍需显示图像回读，不能声明总 host 流量为 0。

本机原始证据保存在 `bench_out/fusion_optimization` 和独立的构建证据目录；公开仓库保留测试脚本及结论，不提交构建输出或测试视频。复查工具：`tests/helpers/fusion_operator_gpu_gate.py`、`fusion_solver_preview_profile.py`、`fusion_4k_profile.py` 和现有 HDR 导出检查。

## 尚未默认接入的研究项

CPU 参考实现已验证热启动只改初值、保留当前帧 `r0` 和统一误差标准。GPU 视频热启动仍未接入：已有时域显示处理不能直接证明它提供了方向、尺寸和遮挡处理正确的残差重投影。把未对齐的历史残差默认加入求解器，需要另外测运动边缘、镜头切换和时间戳不连续。

局部可靠性权重、稳健损失以及按层像素数归一化都会改变画质目标。这轮没有修改生产权重或损失，也没有新增这些选项。应分别用字幕细线、重复纹理、运动和 HDR 高光样本验证后再决定接入。

性能状态仍为 `NOT_CHARACTERIZED`；短测试不代表跨设备、长视频、全部层组合或完整导出性能。
