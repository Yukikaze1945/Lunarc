# 多尺度融合求解器优化

保持 `sum w_i ||D_i r-r_i||² + beta ||r-r0||²`。D 使用现有 Lanczos 计划，转置保留边界重复索引的累加；HDR 残差保持有符号线性 scRGB，CG 核心保持 FP32。单层 NR 不参与这套优化。

## 顺序

1. 保存当前源码、DLL 与短 GPU 测试结果，增加可比较的融合时间、同步次数、等待时间、工作资源容量及原方程残差记录。
2. P0：按真实 tap 数循环；复用不同时存活的工作纹理；CG 参数和状态保留在 GPU，按小批次检查。收敛失败、非有限值和失去正定性仍返回错误。
3. P1：参考实现验证 Jacobi 对角线（先合并边界重复权重再平方）、预条件 CG 和观测空间等价求解。按实际分辨率选择求解空间，保留层间交叉项。GPU 路径通过同一数值标准后接入。
4. 热启动只改变初值，保留本帧 r0 目标；参数、尺寸、视频、场景和时间戳不连续时重置。未验证的光流对齐不作为默认初值。
5. P2：局部可靠性及稳健损失属于不同画质目标，作为独立可选实验评估；不覆盖当前权重含义。

## 检查

- 直接检查真实 D / D^T 配对，含边界、奇数尺寸、非均匀权重、负值及 HDR 高光。
- 原始、预条件、观测空间及热启动求解以同一原方程残差标准比较，并与独立稠密小矩阵结果比较。
- GPU 合成输出误差、目标与一致性下降、明确失败语义、D3D12 验证层、资源复用与每帧重置。
- 短真实 dual/triple GPU 预览或导出，检查独立 NR 会话与单层行为；不把合成求解耗时当成完整渲染速度。
- 记录 NR 推理、融合、迭代、CPU 等待、资源容量及显存采样。没有覆盖的性能与画质范围明确注明。

不使用 Qoder 或子代理；保留工作树中的现有修改。通过验证后仅同步本轮相关文件到公开仓库。

## 本轮结果

GPU 控制包、实际 tap 专用化、7 张全图工作纹理、原方程复查已接入。观测空间和 Jacobi GPU 原型通过数值检查，但测试较慢，保持显式实验。4K 按单轮检查；相对旧版没有实现速度收益，节省约 633 MiB 的工作纹理。热启动已在 CPU 参考中验证，GPU 光流重投影与改变目标的 P2 画质实验保留后续研究。结果和限制见 [多尺度求解器](../multiscale-solver.md)。
