# 后端恢复与显存统计

GPU 设备重置、明确的 CUDA 显存分配失败或原生访问异常会停止新 GPU 任务。由工作台启动的后端会自动重新启动，窗口保持打开，恢复当前视频、参数和帧位置。模型重新加载期间预览会暂停。

同一事件只恢复一次。60 秒内再次失败会停止自动重启，并保留错误提示；恢复失败、旧进程未退出或队列存档不可用时也不会反复启动。普通参数、编码选项错误不触发重启。短暂 HTTP 断连不会被当成 GPU 故障。连接到其他程序启动的后端时，工作台不会擅自终止该进程。

## 导出队列

队列保存到用户数据目录的 `render-queue.json`，使用临时文件、刷新写入和原子替换。在添加、删除、重试、领取任务及任务结束时保存；不在每一帧写磁盘。

- 重启后，正在导出的任务显示为失败并注明“后端重启，导出已中断”。可手动重试，从头导出。
- 待处理、已完成和之前失败的任务保留；不自动继续整个队列或重复运行失败任务。
- 熔断后不继续领取剩余任务，避免把全部任务标成失败。
- 输出文件沿用既有覆盖/跳过规则。不会将未完成文件当成已成功导出，也不承诺从中断帧续编码。
- 存档损坏时保留原文件并报告错误；保存失败的添加、删除和重试不会返回成功。
- 逐帧 GPU 报告不写入队列存档，避免队列文件无限增长。

Windows 后端使用 Job Object 管理子进程，后端异常退出时，所属 FFmpeg 子进程也会结束。熔断前的健康状态和最近一次显存采样保存到同目录的 `last-backend-fault.json`；它是最近采样，不能视为故障瞬间峰值。

## 显存统计

底栏显示本进程 DXGI LOCAL 用量 / 系统预算，整卡占用另列。运行与诊断页显示各阶段已统计的资源分配量、CPU 暂存、预览缓存逻辑容量，以及已加载 PyTorch 的张量/保留缓存。

`GET /api/gpu/memory` 读取最近采样，HTTP 线程不调用 GPU。预览和 GPU 导出在帧边界、所属线程最多约每秒采样一次；关闭后保留上次采样并标记非活跃。

统计口径分别为：

1. DXGI 进程用量与当前系统预算，包括本地和非本地内存。
2. NR/DLAA 颜色、深度、零运动和输出纹理的实际资源分配量；CPU 暂存单独列出。
3. 已提供查询入口的 HDR/SDR10 色彩桥、时间控制桥、Exchange 和融合工作区。
4. 预览缓存逻辑容量、PyTorch 统计。

这些数字不能直接相加。NGX、VSR、VFG、TrueHDR 内部权重/工作区以及编解码器帧池尚不能完整逐项归属；帧边界采样不涵盖 shader 内部瞬时峰值。不会根据“占用很高”推断一定爆显存。

本轮不调整分辨率、精度、模型质量、编码帧池或处理顺序，也不启用 RAM 分块调度。统计用于后续决定资源共享和预算策略。
