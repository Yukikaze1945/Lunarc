# VFG 固定倍率扩展到 16×

## 上游核对

- [ComfyUI NVIDIA VFX 节点](https://github.com/Comfy-Org/ComfyUI_Nvidia_VFX_Nodes/blob/main/__init__.py) 的倍率控件范围为 2–16。执行时设置 `effect.frame_multiplier=M`，对同一对相邻原帧依次运行 `frame_index=1..M-1`。没有多轮 2× 插帧，也没有把生成帧作为下一次生成的输入。
- 进一步读取 NVIDIA 官方索引发布的 `nvidia_vfx-0.2.0.0-cp311-cp311-win_amd64.whl` 中 `nvvfx/effects/video_frame_generation.py`：setter 仅检查倍率不小于 2；`load()` 和 `run()` 直接写入 SDK 的 `FrameMultiplier`，`run()` 写入 `FrameIndex`。此 Python 绑定没有对高倍率另做时间位置转换。源码读取使用 HTTP Range，仅获取 ZIP 目录和该 Python 文件，没有安装或加载 wheel。
- [NVIDIA VFG 文档](https://docs.nvidia.com/maxine/vfx/latest/Filters/VideoFrameGeneration.html) 当前仍将 `FrameMultiplier` 固定模式规定为 2–8，并提供 `FrameMultiplier=0`、`Timestep∈(0,1)` 的时间位置模式。因此，上游节点的 16× 选项不能独立证明本机运行库的固定倍率入口接受 16。

## Lunarc 实现

- 固定倍率接受整数 2–16；布尔值、浮点数及越界倍率继续拒绝。控件、设置类型、输出计划、帮助及四种语言的手册同步。
- 2–8× 保持已有 `FrameMultiplier=M / FrameIndex=i` 调用。9–16× 用已有原生时间位置入口：模型以 `FrameMultiplier=0` 打开，各帧采样 `Timestep=i/M`。16× 对应 `1/16..15/16`。
- 对外仍为固定倍率模式，保留原始帧、原帧率乘 M、时间基分母乘 M；片尾补 M−1 张末帧保持，以保持时长及音轨同步。诊断用 `temporal_selector` 区分时间位置与帧索引。
- 使用同一个 VFG 模型和同一对原帧，复用已有 GPU 输出缓冲区；没有按倍率增加整组输出帧缓存。不改变 SDK 模型质量设置。
- 复用现有 `vfx_framegen_open2` / `vfx_framegen_process_time` ABI，不需要修改或重建原生 DLL。
- 5–16× 保留实验性标识；没有作画质相同、性能或峰值显存的测量承诺。

## 验证范围

CPU 检查覆盖全部 2–16 倍的输出次序、时间戳、尾帧数量、9/16 倍的真实 ABI 参数、SDR8/RGB10A2 路由、分数帧率及编码计划；前端构建通过。

检查时本机仍有导出任务，未进行 GPU 模型测试、实际视频导出或后端重启。需要任务结束后重启软件应用新代码；没有发布安装包。
