# HDR AVIF 图片输入

## 修复

- PQ / BT.2020 AVIF 使用 FFmpeg CPU 高精度解码，转换到线性 Rec.709 scRGB FP16（1 = 80 nit）。处理主图保留负值和大于 1 的分量。
- 图片载入和缩略图生成独立的 SDR 显示副本；此副本不进入模型处理和 HDR 保存。
- 省显存模式从 FP16 开始逐项处理并释放模型；快速模式使用常驻图片处理链，不经过视频 NVDEC / P010 入口。切换素材、参数或模式时关闭旧链。
- 原图对比识别 FP16 HDR。缓存仍仅保留当前和上一份结果。HDR 来源无需另加 TrueHDR 即可选择 HDR 保存。
- 不完整或不支持的 HDR 色彩声明继续拒绝，不能回退成 8-bit SDR。

## 检查

用户提供的 `ACE COMBAT 8 ...1791410085.avif`：3840×2160、yuv444p12le、全范围、BT.2020 / PQ，CLL 590 / FALL 65。

- 实际文件 CPU 主图解码：`float16 (2160, 3840, 4)`，所有分量有限；RGB 范围 -0.3896484375～18.28125，alpha = 1。
- 通过 `image_source.Capture` 成功载入 SDR 显示副本，3840×2160，uint8。原始 12-bit 来源标记与 FP16 工作格式分别记录。
- 解码器合成 PQ 参考：100 nit → 1.25 scRGB，确认归一化基准为 80 nit。
- CPU 回归覆盖解码、处理与显示分离、HDR 初始状态、alpha、原图对比、HDR 保存准入、快速模式复用与释放、不完整标记拒绝；相关图片/路由回归通过。
- `npm run build` 通过。

当前有视频导出任务，未进行 GPU 模型渲染或导出测试，也未重启运行中的后端。代码需要后端重启后加载；本次没有制作或发布安装包。

## 范围

新增输入支持针对完整标记的 BT.2020 / PQ AVIF。本次不扩展高位深 SDR、HLG、HDR HEIC/JXL 或 Ultra HDR JPEG 的主图解码。
