# 图片手动渲染、省显存与两份缓存

2026-10-16。用户在最新一轮允许小范围 GPU 检查，要求避免过量测试。本轮未运行大图、长视频、压力测试或模型遍历。

## 已执行

- Python 定向单元检查：`test_image_render_cache.py`、`test_image_hdr_export.py`，合计 **15 项通过**。检查两份缓存淘汰并回收数组、不可写像素、顺序与 FP16 扩展亮度、清理失败阻断后续阶段、签名/过期判断及 GPU 忙时仍走 CPU 缓存保存。
- `tests/helpers/image_memory_smoke.py`：一张 **257×145 RGBA** 小图，**NR → TrueHDR → VSR 双三次 2×**，省显存模式仅渲染两次，最终 **514×290**。确认每个阶段返回成功释放、模型链/Live 已关闭、结果为线性 FP16、透明度保持、缓存本次与上次两份，以及成对 PNG 显示图。
- 同一小图缓存直接保存 PNG 与 **10-bit BT.2020/PQ、4:4:4、全范围 HEIC**，保持透明度；保存后模型链仍关闭。HEIC 编码入口对实际位深和色彩声明进行检查，不是把 SDR 图片改标签。
- 无后端/GPU 的浏览器交互检查通过：原图可先显示，图片默认手动单帧且省显存，修改参数不会自动推理，切换上次结果不推理，实时开关开启/关闭生效，图片不发送视频 WebSocket 推理命令。原视频手动门控也通过。
- TypeScript、Vite 与 Electron 构建通过；仅既有 bundle 大小提示。

本机证据保存在 `build/image-memory-smoke/evidence.json`，小图和转换文件在同目录；界面截图为 `build/image-preview-controls.png`。均为本地验证产物，不属于发行包。

## 未由本轮证明

- 没有测量大图峰值显存、驱动内部退休行为或跨机器速度。两次小图释放成功不等于所有组合都不会 OOM。
- VSR 此次使用双三次模式验证 FP16 阶段传递、尺寸与释放；未遍历 VSR AI 模式、DLAA、独立放大模型及多层 NR 组合。
- 没有新增原生 DLL 修改或替换；未在真实 HDR 显示器窗口里重做滑块呈现验收。界面调度为模拟后端检查，真实 GPU 检查验证的是处理和完整像素缓存。
- HEIC 已实际保存；AVIF 本轮仅有编码参数单元检查，未实际编码。快速模式沿用完整链路，但未额外运行另一轮 GPU 检查。
