# 图片入口与导出页检查

## 修复范围

原先 PNG 的 `pix_fmt=rgba` 被原生模型的 YUV 输入检查拒绝；只有部分单层 NR 请求会绕到旧图片路径。现在明确区分图片与视频，图片解码、零运动 RGBA GPU 上传、复用已有单层／多层处理、VFX 阶段及最后图像输出。

新增独立的图片保存页与导航入口，导入图片时右上角按钮直达该页。格式、质量、透明度、同名覆盖、保存位置和真实输出尺寸均由控件直接控制。视频导出与队列页面仍可独立访问；加载图片时不允许将图片误加入视频导出表单。

## 已完成的检查

- 相关 Python 单元检查 34 项通过：图片解码／导出与文件保护、原生模型路由、预览消费者、素材加载恢复。
- TypeScript 和 Vite 前端构建通过。
- 用户的 1536×2752 PNG 实际通过 NR→DLAA，完成图片预览与同尺寸 PNG 导出，GPU 会话 generation=1 被复用。不是视频代理或 JPEG 预览文件。
- 513×289 含透明像素的小图实际检查：两层顺序 NR、RTX VSR 2×（1026×578）、TrueHDR→SDR PNG。输出尺寸和透明度均符合期望。
- 独立浏览器界面检查通过：PNG/JPEG 控件切换、质量设置、透明度控件显示规则、保存请求与完成状态。此浏览器检查使用模拟 API；实际 GPU 处理由上述两个 GPU 检查独立确认。
- 界面截图：`build/image-export-gate/ui/image-deliver.png`。
- 原图 GPU 证据：`build/image-export-gate/result.json`、`processed.png`；小图各阶段：`stages.json`；浏览器请求：`ui/result.json`。

## 检查范围与限制

没有宣称所有图片格式、所有 VSR 档位或所有排列已经在真实 GPU 上覆盖，也没有新增性能承诺。TrueHDR 图片导出提供映射后的 8-bit sRGB SDR；16-bit 图片输入明确拒绝。

额外运行旧 `test_gpu_preview_contract.py` 时有两个既有失败：旧 HDR 显示映射数值断言仍使用旧曲线、假 Live 对象缺少当前清理需要的 close 方法。当前文件中对应的生产映射与原有清理代码本轮没有修改；本轮没有将它们算入通过项或修改它们来掩盖失败。
