# 缓存图片原生显示失效修复

## 观察与定位

用户 8K 图片的 `/api/image/render` 成功，`/api/image/results/compare` 随后失败，错误为 `FP16 present: 0x887a0005`。只读查询确认本次与上次的 7680×4320 FP16 结果仍在缓存中。

对原 `gpu_native_presenter.cpp` 的真实像素着色器调用 Windows D3DCompile（与产品相同的 ps_5_1、优化等级），反汇编确认：`first ? A.Load(address) : B.Load(address)` 及 Load2 版本会生成两个资源的 `ld_raw`，再执行 `movc`。地址却由选中一侧的行跨度和像素大小计算。RGBA8 原图与 FP16 结果，或不同尺寸结果之间，这可能访问另一侧资源范围以外的地址。原生 root SRV 不提供缓冲区边界保护。该错误不依赖显存是否耗尽；不能据此断言这次是 OOM。

## 改动

- 以明确的 `[branch] if/else` 分开 A/B 的地址、像素格式与资源读取。色彩公式、处理链、缓存主图和精度不变。
- 原生 GPU 完成等待检查设备状态；错误包含 `GetDeviceRemovedReason`，可用时附上既有 DRED 信息。
- 图片比较/显示的设备失效进入已有后端故障处理，避免继续报告设备健康。前端显示异步原生错误，不再忽略状态接口失败。
- VSR 未上报有效数字档位时不再将数组越界值显示成 `undefined`。
- 显示 DLL 在分离构建目录编译。旧 DLL 被软件占用时留下 pending 标记，关闭软件后从源码启动脚本重开会替换，避免写坏运行中的 DLL。

## 有限验证

- 编译后指令回归检查（CPU，无 GPU）：真实着色器所有 A/B 读取均处于互斥资源选择分支；旧三元写法的负例被检测出来。2 项通过。
- 一轮小尺寸、无模型推理的真实原生窗口检查：257×145 RGBA8 原图与 514×290 FP16 结果，用新编译 DLL 实际完成呈现；上传像素缓冲释放后仍可显示。窗口位于屏幕外，父窗口独立消息线程模拟 Electron，未运行用户 8K 素材。
- 后端故障分类/锁释放定向回归；前端 TypeScript、Vite、Electron 构建。

尚未使用用户 8K 素材重试；没有显存压力测试或速度结论。当前软件仍加载旧 DLL，新的构建需要关闭后重新启动方可使用。缓存可在重启前通过图片导出页直接保存。
