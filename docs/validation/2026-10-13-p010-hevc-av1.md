# P010 HEVC / AV1 10-bit 原生编码

## 已实现范围

GPU P010 帧池与提交路径共用于以下四种 MKV 输出：

| 色彩模式 | HEVC | AV1 |
| --- | --- | --- |
| SDR 10-bit | Main10，limited BT.709 | Main，10-bit，limited BT.709 |
| HDR10 | Main10，limited BT.2020 / PQ | Main，10-bit，limited BT.2020 / PQ |

图片仍使用现有 FP16 处理、色彩桥和 P010 输出。没有改 NR 融合、DLAA/VSR 数学、VFG 插帧算法或音轨字幕封装策略。TrueHDR 的编码调用也接入通用入口，移除了 HEVC 硬限制；本轮没有额外运行完整 TrueHDR 模型验收。

## 原生接口和兼容

- 新增 P010 ABI 1：`nvenc_p010_open`、`nvenc_p010_capability`、`nvenc_p010_get_contract`、`nvenc_p010_get_metadata_status` 和版本查询。
- open 的 `color_mode=0` 为 SDR10 BT.709，`1` 为 HDR10 BT.2020/PQ；codec 从选项选择，HEVC profile 为 `main10`，AV1 为 `main`。FFmpeg AV1 私有 profile 选项使用其真实数值 Main=0，不把 HEVC Main10 传给 AV1。
- 复用旧选项/编码契约布局，旧 HDR、SDR10、普通 SDR ABI 和入口保留。旧 HDR/SDR10 open 继续只接受 HEVC；旧 DLL 只能继续 HEVC，AV1 明确要求新 P010 ABI。
- 传入真实 CUDA context 的新能力查询实际打开并释放相应 P010 NVENC 编码器，不生成文件；没有 context 的查询只描述运行库枚举，不能当作硬件编码证明。最终 open 再验证实际格式、profile、色彩和位深。没有 CPU、8-bit、NV12 或其他 codec 回退。
- CQ、profile、加权预测、B-frame 参考和选项查询按实际 codec 检查。UI 在 SDR10/HDR10/TrueHDR 输出允许 HEVC 和 AV1，保持 MKV/P010；切换 codec 不再强制改回 HEVC。

## 码流元数据

HEVC 保留现有 prefix SEI 137/144 写入器。AV1 在 receive-packet / mux 边界使用独立的低开销 OBU 解析和写入器，写 MDCV type 2、CLL type 1；压缩帧和已有其他 OBU 字节不改变。

AV1 原色顺序为 RGB，色度/白点为 0.16 固定点，最大亮度为 24.8，最小亮度为 18.14，CLL/FALL 为 16-bit 整数。以整数有理数做最近值量化，恰好半单位向上，记录实际 wire 值和误差。原始容器 rational/side-data 保留，不将 HEVC 的 GBR、1/50000、1/10000 网格当作 AV1 网格。

已存在的一致静态元数据不重复写；重复、冲突、坏长度、坏 header、非法 rational、越界和不完整 AV1 mastering 声明明确拒绝。SDR 不生成 HDR metadata，HDR 来源没有声明的字段不补造。诊断区分 HEVC SEI 与 AV1 OBU，码流写入使用独立 bit 16/32，container/encoder/frame side-data 不能代替码流证据。

规范：[NVIDIA NVENC 编码指南](https://docs.nvidia.com/video-technologies/video-codec-sdk/13.0/nvenc-video-encoder-api-prog-guide/)，[AV1 bitstream syntax](https://raw.githubusercontent.com/AOMediaCodec/av1-spec/master/06.bitstream.syntax.md)，[AV1 metadata semantics](https://raw.githubusercontent.com/AOMediaCodec/av1-spec/master/07.bitstream.semantics.md)。

## 本机短验收

RTX 5060 Ti，生产桥接构建，外部模型运行库；测试输出不上传。

| 检查 | 幅面 | 输出帧数 | 结果 |
| --- | --- | ---: | --- |
| 旧 HEVC SDR10 open / P010 编码 | 1280×720 | 4 | Main10、10-bit、BT.709，通过 |
| 新 AV1 SDR10 open / P010 编码 | 1280×720 | 4 | Main、10-bit、BT.709，通过 |
| 旧 HEVC HDR open / P010 编码 | 1920×1080 | 4 | Main10、PQ/BT.2020、SEI，通过 |
| 新 AV1 HDR open / P010 编码 | 1920×1080 | 4 | Main、PQ/BT.2020、Metadata OBU，通过 |
| AV1 SDR10 完整 NR 导出与 remux | 1280×720 | 6 | 25 fps，实际显示 PTS 完整，通过 |
| AV1 HDR10 完整 NR 导出与 remux | 1920×1080 | 6 | 25 fps，裸 AV1 MDCV/CLL，通过 |
| NR → VFG 2× → AV1 SDR10 | 1280×720 | 12 | 50 fps，实际显示 PTS 完整，通过 |

完整导出的最终视频 packet payload 与中间视频一致；音频、字幕 packet payload、章节、附件 extradata/hash、容器标题保留。裸 `.obu` 的 mastering 每个字段均与原始源声明按 AV1 网格量化后的实际 native wire 值一致，CLL/FALL 保持 900/250。该 HDR 样本最大色度误差约 7.4463e-6，最大亮度误差约 4.8828e-6 nit。六个 HDR 帧插入 MDCV/CLL 各六次，共增加 216 bytes。

四种编码边界的 host picture / RGB conversion 字节为 0；完整链路已测 decoder、DLSS、诊断图像和 encoder 图片主机边界也为 0。标量报告回读仍存在，compressed packet/remux 也经过主机，不能声明总 host traffic 为 0。

- 237 项相关 Python 测试通过；53 项前端导出选项/说明测试通过；前端 TypeScript/Vite 构建通过。
- `/W4 /WX` 原生编译通过。AV1 CPU gate 覆盖 wire 顺序、量化、缺失/重复/冲突/坏长度，以及压缩 frame payload 保留。
- 原始证据：本机忽略目录 `build/p010-codec-check/boundary.json`、`driver-capabilities.json`、`build/p010-export-check/export.json` 和对应日志。
- `p010_export_gate.py --recheck` 只离线复查已成功的 GPU 输出，同时修正报告网格标签；不重跑模型。
